# ShiftRecoverPy 项目实施大纲

## 一、项目目标

开发一个Python工具，输入某人的逐日班次与可穿戴设备指标，输出：

1. 这个人的稳定个人基线；
2. 每天偏离基线的程度；
3. 每个轮班工作块结束后的恢复轨迹；
4. 第几天恢复，或者在观察期内尚未恢复；
5. 不同班次类型和连续班次数量之间的恢复时间差异。

项目的核心贡献是一个可复用的方法，不是宣称某个固定数字适用于所有
轮班工作者。

## 二、主要研究问题

### 主问题

在一个连续轮班工作块结束后，个体的睡眠模式需要多少天恢复至其自身
稳定休息日的正常范围？

### 次要问题

1. 连续夜班越多，恢复是否越慢？
2. 睡眠时间、静息心率和活动节律的恢复速度是否不同？
3. 单指标恢复和多指标综合恢复的判断是否一致？
4. 不同恢复阈值、基线天数和“连续恢复天数”设定是否影响结果？
5. 如果未来数据包含BMI、血压或高血压诊断，恢复较慢者是否更常见
   心血管代谢风险？这只能解释为关联，不能解释为因果。

## 三、分析单位和时间锚点

- 数据单位：participant-day，即每人每天一行。
- 暴露单位：shift block，即连续同类班次组成的工作块。
- 时间零点：工作块中最后一个班次的日期，而不是第一个夜班日期。
- 恢复第1天：最后一个班次后的第一个完整日。
- 如果下一个工作块开始或记录结束时仍未满足恢复标准，结果标为
  右删失，而不是擅自填写一个恢复天数。

## 四、第一版使用的指标

### 睡眠时间指标

- sleep_onset_hour：入睡钟点；
- wake_hour：起床钟点；
- sleep_midpoint_hour：睡眠中点；
- total_sleep_hours：总睡眠时长；
- sleep_efficiency：睡眠效率。

钟点变量必须采用圆形时间运算。例如23:30至00:30的差是1小时。

### 心血管和活动指标

- resting_hr：逐日静息心率；
- sleep_hr：睡眠期间平均或最低心率，数据允许时使用；
- HRV指标：数据允许时优先考虑夜间RMSSD；
- steps：每日步数；
- activity timing：每日活动开始时间或活动节律相位。

HRV不能在设备、采样窗口和处理方法不一致时直接混用。

## 五、个人基线的建立

基线不是全体人的平均值，而是每个人自己的稳定休息日。

优先规则：

1. 使用明确标记为休息日的观测；
2. 排除夜班后最初48至72小时的恢复日；
3. 排除紧邻夜班前、明显用于调整睡眠的过渡日；
4. 排除设备佩戴不足和主要睡眠缺失的日子；
5. 第一版至少需要4个合格基线日，正式分析目标为6至8天以上；
6. 中心使用中位数，波动范围使用MAD等稳健统计量；
7. 如果基线不足，输出`insufficient_baseline`，不强行估计。

Mauvieux数据观察期较短，个人基线可能不足，因此主要用于开放数据演示；
TILES约10周，更适合建立个人基线。

## 六、每日偏离分数

每个指标先转换成相对于个人基线的稳健标准化偏离：

```text
指标偏离 = |当天值 - 个人基线中心| / 个人基线波动
```

钟点指标的分子使用最短圆形时间差。综合恢复分数采用多个指标偏离的
均方根，使不同单位的指标能够组合。正式版本需要同时输出：

- 每一个指标的偏离；
- 睡眠域综合分数；
- 心血管域综合分数；
- 活动域综合分数；
- 全部指标综合分数。

综合分数不能代替原始指标，应当作为摘要。

## 七、恢复判定

第一版预设规则：

- 综合偏离分数不高于1.0；
- 连续两个合格休息日满足条件；
- 恢复天数记为这两个连续日中的第一天；
- 缺失日不会被当作恢复；
- 下一个工作班开始后停止当前恢复窗口。

必须进行敏感性分析：

- 阈值：0.75、1.0、1.5；
- 连续日：1天和2天；
- 基线最少天数：4、6、8天；
- 夜班后洗脱期：48小时和72小时；
- 单指标与综合指标。

这些是操作性定义，不是已经获得临床验证的诊断界值。

## 八、数据实施顺序

### 阶段0：合成数据验证——当前已启动

生成28天模拟轮班和可穿戴数据，并且预先知道每个人的真实恢复速度。
程序应当能够大致找回这个已知答案。目的不是制造研究结论，而是检查
算法逻辑、边界情况和删失处理。

完成标准：命令行可运行、产生四张结果表、单元测试通过。

### 阶段1：Mauvieux 2025开放数据

检查下载文件和README，建立字段映射，回答连续五个固定夜班前后睡眠、
体温和血压如何变化。由于只有9天，将结果定位为概念验证，并如实报告
基线不足和删失。

完成标准：第三方可以从公开链接下载数据并一条命令复现结果。

### 阶段2：申请并整理TILES-2018

只下载Main Record，不需要音频数据。优先使用：

- `metadata/days-at-work`；
- `metadata/participant-info`；
- `fitbit/daily-summary`；
- `fitbit/sleep-metadata`；
- 必要时使用`fitbit/heart-rate`和`step-count`。

先在少数参与者上开发读取器，避免每次扫描约100GB完整文件。

完成标准：生成统一的participant-day标准表，但不把原始TILES数据提交
至GitHub。

### 阶段3：主要睡眠恢复分析

识别连续夜班块，根据最后一个夜班对齐，估计每个人及每个工作块的：

- 入睡时间恢复天数；
- 睡眠中点恢复天数；
- 睡眠时长恢复天数；
- 睡眠效率恢复天数；
- 睡眠域综合恢复天数。

比较1、2、3及3个以上连续夜班，并报告删失比例。

### 阶段4：心率和活动扩展

加入静息心率、睡眠心率和活动量。HRV仅在休息日存在质量可靠、定义一致
的记录时进入主要分析，否则作为探索性分析。

### 阶段5：统计推断

恢复时间含有右删失，正式比较优先采用生存分析，而不是只对已经恢复的
人求平均数。候选方法包括Kaplan–Meier曲线、离散时间生存模型，以及按
参与者聚类的bootstrap置信区间。

同一参与者可能贡献多个工作块，模型和重采样必须处理个体内相关性。

### 阶段6：敏感性分析和质量控制

- 更换恢复阈值；
- 更换基线定义；
- 排除佩戴不足日；
- 按工作块之间休息日数量限制分析；
- 分别分析固定夜班和白班人员；
- 检查夏令时、跨午夜和时区问题；
- 显示每位参与者的轨迹图，人工检查异常案例。

### 阶段7：GitHub成品

最终仓库应包含：

- 英文README；
- 安装和一键运行命令；
- 数据下载与许可说明；
- 清晰的Python包结构；
- 自动测试；
- 示例notebook；
- 方法流程图；
- 可复现结果表和图片；
- 局限性与数据治理声明。

## 九、项目边界

第一版不承诺：

- 给出医学上通用的“正常恢复”诊断；
- 从观察性数据证明轮班导致高血压；
- 使用短期数据可靠预测长期心血管疾病；
- 公开Airwave或TILES受限的参与者级数据。

第一版要完成的是一个透明、经过测试、可应用到不同可穿戴指标的个体化
恢复时间估计框架。
